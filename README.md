# AULA Codex RGB

**AI 작업의 흐름을 키보드의 빛과 LCD 경과시간으로 보여 주는 Windows 앱입니다.**

USB-C로 연결한 **AULA F108 Pro**를 로컬 **Codex·Work**의 작업 상태에 연동합니다. 생각 중에는 파랑과 흰색의 생명 파동이, 문서를 읽을 때는 흰색 파동이, 코드를 수정할 때는 파란 배경 위의 짧은 흰색 스캔이 나타납니다.

**기본 설정: 밝기 65% · 10fps · F1~F12도 전체 효과에 함께 반응**

[**Windows 앱 다운로드**](https://github.com/kim-DL/aula-codex-rgb/releases/latest) · [설치하기](#설치하기) · [상태별 색상과 효과](#상태별-색상과-효과) · [LCD 동작](#lcd-동작) · [문제 해결](#문제-해결)

## 먼저 확인해 주세요

| 항목 | 지원 범위 |
| --- | --- |
| 운영체제 | Windows 10/11 **x64** |
| 키보드 | **AULA F108 Pro**, USB-C **유선** 연결 |
| 장치 식별자 | VID `0C45` · PID `800A` |
| 작업 연동 | 데스크톱의 **로컬 Codex·Work** 작업, 활성화된 Codex 훅과 로컬 세션 기록 |
| 실행 준비 | 배포 ZIP 사용 시 **Go 설치 불필요**, 드라이버 교체·관리자 서비스 불필요 |

일반 **ChatGPT 모드**, 클라우드 작업, Bluetooth·2.4GHz 연결, 다른 RGB 키보드는 현재 확인한 지원 범위에 포함되지 않습니다. 같은 모델도 펌웨어나 Codex 업데이트에 따라 호환성 재확인이 필요할 수 있습니다.

## 설치하기

### 1. 다운로드하고 압축 해제

1. [최신 릴리스](https://github.com/kim-DL/aula-codex-rgb/releases/latest)에서 이름이 `windows-amd64.zip`으로 끝나는 파일을 받습니다. 현재 버전은 `aula-codex-rgb-v0.1.1-windows-amd64.zip`입니다.
2. ZIP **전체**를 앞으로 계속 사용할 폴더에 압축 해제합니다. 예: 사용자 문서 폴더의 `AulaCodexRgb`.
3. 압축 해제 후 아래 두 파일이 **같은 `bin` 폴더**에 있는지 확인합니다. ZIP 안에서 직접 실행하지 마세요.

```text
AulaCodexRgb/
├─ Install.cmd                      ← 더블클릭 설치·실행
├─ Run.cmd                          ← 더블클릭 실행
├─ Uninstall.cmd                    ← 더블클릭 종료·연동 제거
├─ bin/
│  ├─ aula-codex-rgb-background.exe   ← 실제 백그라운드·트레이 앱
│  ├─ aula-codex-rgb.exe              ← 설치·실행·상태 확인용 명령 도구
│  └─ aula-codex-rgb-setup.exe        ← 한국어 설치·제거 안내 창
├─ docs/                            ← 설치 안내와 검증 범위
├─ licenses/                        ← 서드파티 라이선스
├─ README-ko.md
├─ SHA256SUMS.txt
└─ VERSION.json
```

실행 파일은 **디지털 서명이 없는 개인 프로젝트 배포본**입니다. Windows 또는 조직 정책에 따라 추가 확인이나 실행 제한이 있을 수 있습니다. 릴리스에 함께 있는 `SHA256SUMS.txt`로 내려받은 ZIP의 해시를 비교할 수 있습니다.

```powershell
Get-FileHash .\aula-codex-rgb-v0.1.1-windows-amd64.zip -Algorithm SHA256
```

### 2. 더블클릭으로 설치·실행

압축 해제한 폴더의 **`Install.cmd`를 더블클릭**하고 한국어 확인 창에서 **예**를 누릅니다. PowerShell 명령을 입력할 필요가 없습니다. 설치 후 바로 앱 실행을 요청하고, 다음 Windows 로그인부터 자동 실행되도록 등록합니다.

| 파일 | 더블클릭하면 |
| --- | --- |
| **`Install.cmd`** | 현재 사용자 자동 실행·Codex 훅 등록 후 앱 실행 |
| **`Run.cmd`** | 설치 등록을 바꾸지 않고 앱 실행 |
| **`Uninstall.cmd`** | 확인 후 앱 정상 종료를 기다리고 자동 실행·이 설치 위치의 훅 제거 |

설치·제거 결과와 오류는 한국어 창으로 안내합니다. 다른 위치의 AULA RGB가 자동 실행에 등록되어 있으면 작업을 멈추고 기존 위치에서 먼저 제거하도록 안내합니다. 앱 폴더·사용자 설정을 자동 삭제하거나 관리자 권한을 요청하지 않습니다.

**탐색기에서 실행**하고, 설치 후 폴더를 옮기지 마세요. 기존 명령 방식이 필요한 분은 아래를 참고하세요.

<details>
<summary>고급 사용자용: PowerShell로 설치·실행</summary>

**Windows 시작 메뉴에서 일반 PowerShell을 열고**, 압축 해제한 폴더로 이동합니다. 아래 예시는 문서 폴더에 `AulaCodexRgb`라는 이름으로 풀었을 때입니다. 다른 위치라면 첫 줄을 실제 경로로 바꾸세요.

```powershell
Set-Location (Join-Path ([Environment]::GetFolderPath('MyDocuments')) 'AulaCodexRgb')
.\bin\aula-codex-rgb.exe install
.\bin\aula-codex-rgb.exe run
```

`install`은 현재 사용자의 **Windows 로그인 자동 실행**과 **AULA용 Codex 훅**을 등록합니다. 기존 훅 파일이 있으면 백업하고 다른 훅을 보존하면서 이 앱 항목을 추가합니다. `run`은 트레이 앱을 백그라운드로 시작하며, PowerShell 창을 닫아도 앱은 계속 실행됩니다.

Codex 내부 터미널에서 설치하면 패키지의 경로·레지스트리 가상화로 로그인 자동 실행 위치가 달라질 수 있으므로 **일반 PowerShell**을 사용하세요. 등록 명령에 설치 경로가 들어가므로 설치 후 폴더를 옮기지 않는 편이 좋습니다.

</details>

### 3. Codex 훅 검토와 첫 동작 확인

사용 중인 Codex에서 훅 기능이 활성화되어 있어야 합니다. 제품이 훅 검토·신뢰 등록을 요구하면 **추가된 AULA 명령을 확인한 뒤 제품의 정상 절차로 등록**하세요. 앱 설치만으로 훅 신뢰 등록이 끝나는 것은 아닙니다. 앱은 신뢰 설정이나 승인 정책을 우회하지 않습니다.

작업 표시줄의 숨겨진 아이콘 영역(`^`)에서 **AULA RGB** 트레이를 확인한 다음, 로컬 Codex·Work에서 파일을 읽거나 도구를 실행하는 요청을 보내 보세요.

| 확인할 것 | 정상 동작 |
| --- | --- |
| 작업이 없을 때 | 낮은 샌드빛 위로 부드러운 흰빛이 유영 |
| 요청을 처리할 때 | 감지된 상태에 맞춰 색상·효과 전환, LCD 경과시간 증가 |
| 실제 작업이 끝났을 때 | 초록 완료 파동을 거쳐 샌드빛 대기로 전환, LCD는 PC 날짜·시각으로 복귀 |
| 타이핑 | 기존처럼 정상 입력 |

다른 작업이 동시에 진행 중이면 그 작업이 계속 표시될 수 있습니다. 실행 상태는 아래 명령으로도 확인합니다.

```powershell
.\bin\aula-codex-rgb.exe status
.\bin\aula-codex-rgb.exe lcd-status
```

## 상태별 색상과 효과

색상은 작업의 의미를, 움직임은 작업의 흐름을 표현합니다. **밝기 65%는 공통 설정**이며, 차분한 대기 조명과 애니메이션의 바탕·중심은 서로 다른 강도로 빛납니다.

| 상태 | 색상 | 실제 효과와 의미 |
| --- | --- | --- |
| **생각 중** | 🔵 파랑 + ⚪ 흰색 | 파란 배경 위로 흰빛 중심이 살아 움직이듯 호흡하는 **생명 파동**. 작업이 진행 중이고 다른 활동 신호가 없는 구간의 **추정 표시**입니다. |
| **코드 작성·수정** | 🔵 파랑 + ⚪ 흰색 | 파란 배경 위를 **짧고 선명한 흰색 스캔**이 지나갑니다. 뒤쪽 약 한 키 길이의 잔광으로 이동 방향을 보여 줍니다. |
| **문서·파일·자료 읽기** | ⚪ 흰색 | 위에서 아래로 흐르며 여운을 남기는 **문서 파동**. 짧은 읽기는 약 **1.8초의 여운**으로 알아보기 쉽게 표시합니다. |
| **문서 수정** | ⚪ 흰색 | 읽기와 같은 **문서 파동**을 사용합니다. 읽기·수정 여부는 트레이의 작업 상태에서 구분합니다. |
| **일반 도구 실행** | 🟡 노랑 | 방향성 있는 빛과 짧은 궤적이 이동합니다. 도구 종류·동시 실행 상황에 따라 모션에 변주가 있습니다. |
| **승인·입력 대기** | 🟡 노랑 | 전체 키보드의 양쪽 빛결이 **중앙으로 모였다가 다시 열리는 모션**. F열이나 Enter에만 표시하지 않습니다. |
| **응답 활동** | ⚪ 흰색 | 메시지 활동을 감지하면 **흐르는 흰빛과 잔광**으로 표현합니다. 실제 토큰 생성 속도를 나타내지는 않습니다. |
| **작업 완료** | 🟢 초록 | **퍼지는 완료 파동** 후 샌드빛 대기로 부드럽게 연결합니다. 다른 작업이 진행 중이면 그 작업 표시가 우선합니다. |
| **오류·중단** | 🔴 빨강 | 완만한 두 번의 맥동과 오류 표시. 도구 실패·턴 실패·사용자 중단은 상태 엔진에서 구분합니다. |
| **대기** | 낮은 샌드빛 + ⚪ 흰빛 | 차분한 샌드 바탕 위로 흰빛이 천천히 유영하며 은은한 움직임을 만듭니다. |

**같은 파랑·흰색이어도 효과가 다릅니다.** 생각 중은 흰빛이 커졌다 작아지는 호흡이고, 코드 작업은 흰빛이 짧게 이동하는 스캔입니다. 문서 읽기·수정과 응답 활동은 흰색을 공유하지만 파동과 이동 방식이 다릅니다.

F1~F12는 전체 효과에 함께 반응합니다. **F키를 작업별 상태 표시등으로 고정하지 않습니다.** 상태 사이에는 연결 모션을 사용하며, 10fps에서도 움직임의 속도는 경과시간을 기준으로 계산합니다.

### 여러 작업이 동시에 실행되면

키보드 전체는 우선순위가 높은 작업을 표시합니다.

**승인·입력 대기 → 오류·중단 → 문서 읽기·수정·코드 작업 → 일반 도구 실행 → 응답 활동 → 생각 중 → 완료**

따라서 한 작업이 끝나도 다른 작업이 진행 중이면 곧바로 샌드빛이 되지 않을 수 있습니다. 트레이의 **Codex 작업** 메뉴에서 작업별 상태와 **확정·추정**, 상태 확인 지연 여부를 확인할 수 있습니다.

### 감지 범위와 정확성

앱은 Codex 훅과 읽기 전용 로컬 세션 기록을 함께 사용합니다. 임시 내부 대화·자동 제안은 명시적인 임시 세션 신호가 있을 때 제외합니다.

- **생각 중**은 모델의 내부 사고를 직접 측정한 값이 아닙니다.
- **응답 활동**은 메시지 이벤트를 바탕으로 하며, 토큰 스트리밍 시작이나 속도를 측정했다고 해석하면 안 됩니다.
- **코드 작업·문서 작업**은 확인 가능한 도구·파일 활동을 분류합니다. 사용자 본인이 다른 편집기에서 타이핑하거나 파일을 여는 모든 행동을 감시하지 않습니다.
- **읽기**는 지원되는 읽기 도구와 단순 본문 조회를 대상으로 합니다. 복잡한 스크립트·혼합 명령은 일반 도구 실행으로 남을 수 있습니다.
- **완료**는 실제 턴 종료 기록으로 판정합니다. 일부 로컬 이벤트는 실행 후 기록되므로 조명 전환이 늦거나 짧은 상태를 보기 어려울 수 있습니다.

## LCD 동작

키보드의 **기본 시계 숫자**를 활용합니다. 별도 이미지나 작업 이력 화면을 저장하지 않습니다.

| 상황 | LCD 표시 |
| --- | --- |
| 작업 없음 / 데스크톱 앱이 실행되지 않음 | PC의 **현재 날짜·시각** |
| 로컬 요청 시작 신호 감지 | `00:00:00` 기준 **경과시간** 시작. 늦게 도착한 신호는 감지된 시작 시각을 반영 |
| 작업 진행 중 | 경과시간 증가. 날짜는 **PC 날짜** 사용 |
| 실제 요청 종료 신호 감지 | **PC 날짜·시각으로 복귀**. 완료 시간을 LCD에 고정하지 않음 |
| 새 요청 시작 | 새 요청의 경과시간으로 다시 시작 |
| 여러 요청이 겹침 | **가장 최근에 시작한 요청 한 건**을 표시. 그 요청이 끝나면 PC 시각으로 복귀하며, 이전 요청 타이머로 돌아가지 않음 |

LCD는 최신 요청 한 건을, RGB는 여러 작업의 우선순위를 표시하므로 두 표시가 서로 다른 작업을 반영할 수 있습니다. 경과시간 표시는 24시간 미만을 대상으로 하며 그 이후에는 PC 시각으로 돌아옵니다.

**최근 완료 결과 한 건만 RAM에 유지**하고 앱을 종료하면 지웁니다. 소요시간 이력 파일이나 DB를 만들지 않습니다. 실행 중 최근 결과는 `lcd-status`로 조회할 수 있습니다. 키보드를 분리하거나 앱을 강제 종료한 경우에는 즉시 PC 시각으로 복귀하는 것을 보장하지 않습니다.

## 일상 사용·종료·제거

설치 후에는 **Windows 로그인 시 자동 실행**됩니다. 수동 실행은 **`Run.cmd` 더블클릭**, 연동 제거는 **`Uninstall.cmd` 더블클릭**으로 진행하세요. 현재 실행만 종료하려면 트레이의 **종료**를 사용합니다. CLI 파일만 더블클릭하면 상주 앱이 시작되는 방식이 아닙니다.

아래는 고급 사용자용 명령입니다. 더블클릭 설치에는 입력하지 않아도 됩니다.

| 하고 싶은 일 | 방법 |
| --- | --- |
| 실행 | `.\bin\aula-codex-rgb.exe run` |
| RGB 상태·설정 확인 | `.\bin\aula-codex-rgb.exe status` |
| LCD 동작·최근 결과 확인 | `.\bin\aula-codex-rgb.exe lcd-status` |
| RGB 반응 일시 정지 | 트레이 **일시 정지 / 재개** 또는 `.\bin\aula-codex-rgb.exe pause` |
| RGB 반응 재개 | 트레이 **일시 정지 / 재개** 또는 `.\bin\aula-codex-rgb.exe resume` |
| 이번 실행 종료 | 트레이 **종료** 또는 `.\bin\aula-codex-rgb.exe stop` |
| 자동 실행·훅 연동 제거 | 실행 종료 후 `.\bin\aula-codex-rgb.exe uninstall` |

`stop`은 현재 앱을 종료하며 로그인 자동 실행 등록은 유지합니다. `Uninstall.cmd`는 종료 확인과 연동 제거를 순서대로 처리합니다. 제거 완료 안내 뒤 앱 폴더를 직접 정리할 수 있습니다. 사용자 설정과 다른 Codex 훅은 유지합니다.

## 업데이트하기

1. 기존 앱을 트레이 또는 `stop`으로 정상 종료합니다.
2. 기존 실행 파일과 필요한 사용자 설정을 보관합니다.
3. 새 ZIP의 내용을 기존 설치 폴더에 풀어 **실행 파일과 CMD 파일을 함께 교체**합니다.
4. `Run.cmd`를 더블클릭해 실행하고 트레이와 실제 작업 반응을 확인합니다.

설치 위치를 바꾸려면 **이전 위치에서 먼저 제거**, 새 위치에서 `Install.cmd`를 실행하세요. v0.1.0에서 이동하는 경우 이전 폴더의 CLI로 `stop` → `uninstall`을 먼저 진행합니다. 새 훅 내용이 제품의 신뢰 검토를 요구하면 정상 절차로 다시 확인합니다. 다운로드용 파일은 개인 설정·훅 사본·대화 기록·PC별 복원 백업을 포함하지 않습니다.

## 문제 해결

| 증상 | 먼저 확인할 것 |
| --- | --- |
| CMD 실행 시 파일이 없다고 나옴 | ZIP 전체를 풀었는지, `bin/aula-codex-rgb-setup.exe`를 포함한 세 EXE가 있는지 확인합니다. |
| 다른 위치에 설치되어 있다고 나옴 | 기존 설치 위치에서 먼저 제거하세요. 다른 설치를 덮어쓰거나 임의로 종료하지 않도록 막는 안내입니다. |
| 설치 명령을 찾을 수 없음 | 현재 폴더 바로 아래에 `bin`이 있는지 확인합니다. ZIP을 풀었을 때 생긴 한 단계 안쪽 폴더로 이동해야 할 수 있습니다. |
| 트레이 아이콘이 안 보임 | 작업 표시줄의 숨겨진 아이콘(`^`)과 `status`를 확인합니다. `run`은 별도 창을 띄우지 않습니다. |
| 로그인 후 자동 실행이 안 됨 | 설치 폴더를 옮기지 않았는지, Windows 시작 앱에서 AULA 항목을 꺼두지 않았는지 확인합니다. 일반 PowerShell에서 등록했는지도 확인하세요. |
| 샌드빛은 보이는데 작업에 반응하지 않음 | 일시 정지 여부, 로컬 Codex·Work 작업인지, 훅 활성화·검토·신뢰 등록 여부를 확인합니다. |
| 작업 종료 후에도 파랑·노랑이 남음 | 다른 실행 중 작업이나 승인 대기가 있는지 트레이의 **Codex 작업**을 확인합니다. 정상 종료 기록 수신이 늦을 수도 있습니다. |
| 문서 읽기가 노랑으로 보임 | 도구나 명령을 안전하게 읽기로 판별하지 못하면 일반 도구 실행으로 표시합니다. |
| LCD가 PC 시각으로 돌아오지 않음 | `lcd-status`에서 진행 중인 요청과 오류를 확인합니다. 종료 신호 수신·USB 연결 문제를 구분해야 합니다. |
| USB 분리 후 반응하지 않음 | 유선 재연결 뒤 트레이의 USB 상태를 확인합니다. 앱은 재연결을 시도하며 반복 오류 시 전송을 중지할 수 있습니다. |

앱은 중복 실행과 여러 USB 전송기의 동시 소유를 막습니다. 다른 RGB 제어 프로그램이나 개발용 하드웨어 시험과 함께 장치를 제어하지 마세요. 문제가 계속되면 [Issues](https://github.com/kim-DL/aula-codex-rgb/issues)에 Windows·Codex·앱 버전, 연결 방식과 재현 순서를 남겨 주세요. 개인 대화 내용이나 인증 정보는 올리지 마세요.

## 장치·데이터 처리

- 정상 상주 경로는 단일 HID 연결로 **휘발성 RGB 프레임과 LCD 시각 동기화**를 직렬 전송합니다. 드라이버 교체·관리자 서비스·플래시 프로필 저장을 하지 않습니다.
- 설정과 기술 상태는 현재 사용자의 `%LOCALAPPDATA%\AulaCodexRgb`, 훅은 `%USERPROFILE%\.codex\hooks.json`에 둡니다.
- 대화 본문·문서 내용·명령 전문·LCD 작업 시간 이력을 진단 로그에 추가하지 않습니다. 진단 상세 로그는 기본 비활성입니다.
- Windows 로그인 전의 부팅 조명은 이 앱의 실시간 제어와 별개입니다. 이 배포본의 설치가 키보드 저장 프로필을 바꾸지는 않습니다.
- 정상 종료 시 차분한 조명과 PC 시각 복귀를 시도합니다. 장치 분리·강제 종료 시 복귀를 보장하지 않습니다.

## 개발자용 빌드와 구조

배포 ZIP을 사용하는 분은 이 과정이 필요하지 않습니다. 소스 빌드는 Windows와 **Go 1.24.5 이상**을 사용하며, 현재 스냅샷은 Go 1.27.2로 검사했습니다.

PowerShell에서 저장소 루트를 작업 폴더로 사용하고 Go를 PATH에 등록합니다.

```powershell
.\Build.ps1 -TestOnly
.\scripts\Test-Launchers.ps1
.\Build.ps1 -Candidate
.\Build.ps1
```

별도 Go 경로는 `-GoExe 'C:\Tools\go\bin\go.exe'`로 지정합니다. 결과는 `bin/`에 생성합니다. 실행 중인 앱과 같은 경로에 빌드하려면 먼저 정상 종료하거나 `-Candidate`를 사용하세요. 위 검사는 키보드를 여는 upstream 하드웨어 테스트를 실행하지 않습니다.

| 경로 | 내용 |
| --- | --- |
| `app/` | 상주 앱, 트레이, 상태 엔진, 읽기 분류, LCD 컨트롤러, 애니메이션·검사 |
| `app/cmd/` | 미리보기·실기·실험 개발 도구. USB·영구 설정 관련 도구는 자동 실행되지 않음 |
| `upstream/` | `parsiya/f108-pro`의 수정 소스 스냅샷. 원본 라이선스 보존 |

오프라인 미리보기는 `app` 폴더에서 `go run ./cmd/preview ../preview`로 생성합니다.
